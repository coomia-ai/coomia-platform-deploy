# 安全说明

[English](security.en.md) | 简体中文

## 安全边界

本交付包不包含应用源码、Dockerfile、License 私钥或客户凭据。产品镜像应由交付方以固定 RepoDigest 发布，并在发布清单中记录 SBOM、签名验证和源码残留扫描证据。

代码保护提高逆向成本，但不能替代访问控制、授权校验、镜像签名、漏洞管理和法律许可条款。

## 凭据与密钥

- `compose/.env` 权限必须为 `0600`，备份必须加密。
- 项目凭据由 API 自动生成并原子保存；`MDS_INTAKE_SECRETS_DIR` 必须为 API 独占的持久化目录，权限为 `0700`，其中记录权限为 `0600`。
- 不得复用 JWT、HMAC、数据库、Redis、对象存储或 Flink 控制密钥。
- License 私钥只保留在交付方签发环境。
- 密钥泄露后应立即吊销或轮换，并评估已签发令牌和备份。

## 网络

基础设施服务默认只加入内部网络，不映射主机端口。UI 和 API 应部署在客户反向代理后，由其提供 TLS、访问控制、限流和审计。可选管理端口只能绑定 `127.0.0.1`。

## 容器与主机

保持 Docker、Linux 内核和第三方镜像处于受支持版本。限制 Docker 组成员，因为 Docker 访问等同于主机高权限。Flink 网关仅挂载只读 Docker 套接字，但仍属于高敏感组件，应限制网络访问和令牌使用。

## 数据保护

RustFS bucket 默认不配置匿名策略。备份、日志和导出文件应执行客户数据分级、加密、保留和销毁策略。任何排障操作都不得把生产数据上传到未经批准的系统。

## 漏洞响应

发现安全问题时，保留版本、镜像摘要、时间线和最小必要日志，停止扩大影响的操作，并通过合同约定的安全渠道联系交付方。不要在公开渠道披露利用细节或凭据。
