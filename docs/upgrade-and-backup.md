# 升级、备份与回滚

[English](upgrade-and-backup.en.md) | 简体中文

升级属于生产变更。必须在隔离环境完成演练，并由客户批准维护窗口和回滚条件。

## 备份范围

至少备份：

- PostgreSQL 数据库及恢复所需角色信息。
- MinIO、Doris、TuGraph、Kafka、Redis 的持久化数据。
- `license-state` 卷。
- `compose/.env`、生成配置目录和当前发布材料。
- `VERSION`、镜像 RepoDigest、备份时间和校验和。

仅复制运行中容器的数据目录不构成一致性备份。应使用各组件支持的备份方法，并验证恢复。

## 升级流程

1. 阅读发布说明和已知问题，确认升级路径。
2. 在隔离环境执行升级与回滚演练。
3. 停止业务写入，记录 Flink 作业状态并完成一致性备份。
4. 保存当前 `compose/.env` 和镜像摘要。
5. 替换部署包，只填入新版本批准的 RepoDigest。
6. 执行 `bash install.sh compose`。
7. 完成健康检查和业务验收，再恢复流量。

不得使用 `latest`、临时 tag 或未列入发布清单的镜像。

## 回滚

如果数据库或数据格式未发生不可逆变更，可恢复上一版本部署包和镜像摘要。若存在迁移，则必须按照该版本发布说明恢复备份。应用版本、数据库、对象数据和 License 状态必须恢复到一致时间点。

## 恢复演练

每个正式版本至少完成一次空环境恢复演练，记录恢复点目标、恢复时间目标、数据校验结果和负责人。未经恢复验证的备份不能视为可用备份。
